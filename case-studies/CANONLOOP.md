# CANONLOOP

생성형 미디어의 연속성과 수정 계보를 추적

## 문제와 제품

다양한 장면·포맷의 결과를 입력/출력 계약, 수정 계보, 승인 및 provenance로 연결합니다.

## 저장소에서 확인할 설계

- 8개 bounded agent 계약, 허용 도구·실패·재시도 정책
- Python/FastAPI와 React/Next.js guided replay
- 승인된 결과 packaging 및 repair lineage

## 증거와 검증

기존 감사는 checked-in submission manifest와 MockProvider 증거를 검토했습니다. 체크인 attestation은 독립 CI가 아닙니다.

[소스 저장소](https://github.com/estona815/CANONLOOP) · [검토한 README 고정 SHA](https://github.com/estona815/CANONLOOP/blob/8731c7c6d52239f3d361a445fcf0d92ae6567a88/README.md)

## 범위와 개인 기여

deterministic fixture 기반 replay입니다. live 생성·B2·자율 운영·수상·개인 전면 저작을 주장하지 않습니다.

개인별 기여는 [증거 기준](../docs/EVIDENCE.md)을 따릅니다. 저장소 구현 설명을 후보자의 모든 코드 직접 작성 증거로 해석하지 않습니다. AI 활용 내역은 각 원본 저장소의 disclosure를 우선합니다.
